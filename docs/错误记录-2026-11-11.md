# 错误记录（2026-11-11，本轮返工）

## E-101 改错代码副本
现象：所有改动都在线上看不到。
原因：本地有两份代码，`survey-panel`（无 git 的旧副本）和 `.tmp-changelog/fe`（真仓库）。我在旧副本上改、构建、看截图，全部无效。
教训：动手前先确认 `git remote -v` 和 `git log`；没有 `.git` 的目录一律当副本，不当源码。

## E-102 把内部动作放进了客户页面
现象：客户的研究工作台出现“发送合同/发报告/发布结果”。
原因：没区分管理端（内部）和研究端（客户）。这些是运营动作，客户只能签收。
教训：任何按钮先问“谁按”，客户页只出现客户自己的动作。

## E-103 指错入口
现象：说“管理员端在 /admin/client-projects”，但实际在用的是 `/admin` 的中文「项目与订单」。
原因：仓库里有两套管理页（英文 AdminBusinessProjects、中文 AdminList），我只改了前者就宣布完成。
教训：说“入口在哪”之前，先按用户的截图确认是哪个路由。

## E-104 页签只换样式不筛数据
现象：「项目与订单」四个页签点哪个都一样。
原因：`AdminList` 里 `tab` 只控制 `is-active`，从未参与过滤。
修复：模块提供 `filterRows(rows, tab)`，列表按它截取。

## E-105 一行塞六个字段
现象：项目列表读起来挤。
原因：名称、状态、形式、回收、日期、动作、菜单全在一行。
修复：先改两行，后按 YouGov 改成卡片；状态徽标进卡片头，描述移入详情。

## E-106 表格语言混排
现象：`Projects | 状态 | 形式 | 回收 | 创建`。
原因：部分表头走英文文案，部分走代码里的中文兜底。
修复：表头标签按当前语言统一取值。

## E-107 图表里硬编码中文
现象：英文界面环形图出现“其他”。
原因：`ResultsChart` 里写死 `'其他'`。
修复：改为 `otherLabel` 参数，按语言传入。

## E-108 崩溃页不给原因
现象：工作台崩溃后只有一个“Reload”。
修复：`ErrorBoundary` 把错误信息直接显示在页面上，方便下一轮定位。

## E-109 改完不回滚验证就宣布上线
现象：多次说“已上线”，实际包没变（构建排队/失败）。
教训：每次发布后必须取线上 `index-*.js` 并 grep 本次字符串；哈希没变就是没上线。

## E-110 用整页刷新代替状态更新
现象：操作完成后 `window.location.reload()`。
修复：工作台改为 `reloadKey` 触发数据重取；管理端仍是刷新，待改。

## E-111 用了组件但没 import
现象：研究端点「查看详情」整页变成崩溃页，只有一句 `BusinessProjectSheet is not defined`。
原因：`BusinessWorkspace` 引用了弹窗组件但忘了 import；`AdminBusinessProjects` 同样缺 `BusinessProjectActions`。构建不报错，运行时才炸。
教训：新入口写完必须真点一次；另外跑一遍「JSX 里用到但没声明」的静态扫描。

## E-112 带 #root 的规则压过手机断点
现象：390 宽下侧栏还是 236px，正文被挤到 154px，页面横向溢出 100px。
原因：`#root .business-workspace-body` 的 ID 选择器权重高于后面所有 `.class` 媒体查询。
教训：ID 前缀的布局规则要在同一份规则里重写断点；验收至少看 1440 / 1024 / 390 三档截图。

## E-113 研究端又长回「放行报告」
现象：问卷中心（客户页）每张卡上还有「放行报告 / 撤回」，点完提示“报告已放行，客户现在可以打开结果页”。
原因：上一轮只删了项目卡片上的一处，另一处没删；同一句话里还把用户自己叫「客户」。
教训：内部动作按“谁按”全仓搜一遍，不要只改截图里那一处。

## E-114 状态码和英文直接上屏
现象：问卷中心徽标印 `PUBLISHED` / `PENDING_REVIEW`；中文结果页的导出、下载、筛选等按钮全是英文。
原因：徽标只查了项目状态表，没有问卷状态；中文结果页缺 15 个键，回落英文基座。
教训：任何状态上屏前先过一层文案表；补文案时按 key 对一遍 en 基座。

## E-115 开发占位文案写进了客户界面
现象：客户能看到「改密接口还没接上」「接受接口还没接上」「AI 接口还没接上（后端待加 /assist）」「进人判断在后端」「Mock 模式」「Mock 文档用例」。
原因：占位文案是写给自己人看的，一直没换成产品语言；有的还带后端路径。
教训：客户页每句话按「客户读到会怎么想」过一遍；“接口 / Mock / 后端”这些词一个都不许出现。

## E-116 崩溃页把 JS 报错原文给客户看
现象：客户看到 `BusinessProjectSheet is not defined`，下面还写着“可能是浏览器扩展或翻译插件改动了页面”，全英文。
原因：上一轮为了好定位，把 error.message 直接渲染；顺手把锅甩给了用户浏览器。
教训：崩溃页只说“发生了什么 + 怎么办”，技术细节只在开发环境出现。

## E-117 报告里把「团队标志」写成「日志上传」
现象：复审报告写“假的日志上传控件”，看的人找不到东西——研究端根本没有日志上传。
原因：标志（logo）打成日志，描述失真比代码 bug 更耽误人。
教训：报告里出现的每个名词，回代码里搜一遍再用。

## E-118 报价页的「去付款」是个死循环
现象：点「去付款」跳充值页，充完回来再点，还是跳充值页；项目永远不会被扣款。
原因：报价页把付款按钮直接写成跳 `/business/add-funds`，没有调用项目付款接口。余额还写死显示「—」。
教训：同一个动作（付款）只允许一个实现；按钮文案相同的两个入口，必须走同一条链路。

## E-119 把自助流程当成了送审流程
现象：自助调查页写着“项目已送审，报价不能再改”；「下一步：问卷」点进去是报价页；步骤条永远停在「问卷构建」，「报价与付款」点不动。
原因：研究端有两条线——自助（受众→问卷构建→报价与付款→发布投放）和定制（送审→报价→合同→付款→质检→客户确认→交付）。页面文案和导航按定制线写，自助客户被卡住。
教训：改任何一页先确认它属于哪条线；自助线里不许出现“审核 / 送审 / 确认问卷”。

## E-120 同一个项目，两个价格
现象：受众页写 US$1.92/份、合计 US$480.83；报价页写 US$3.50/份、合计 US$901.25。同一个项目、同一份受众。
原因：受众页自己写了线性估价（0.72 衰减），报价页用价目表（0.82 衰减 + 分档），两套公式各算各的。
教训：价格只能有一个来源；先有 rateCard 再写页面，任何页面都不许自己拼价格公式。

## E-121 六轮复审都没发现“第二个价格公式”（我自己的错）
现象：受众页 US$1.92/份、US$480.83；报价页 US$5.80/份、US$1,493.50。两个页面同时在线，客户一比就看到约 3 倍价差，等于把定价空间摆在客户面前。
原因：
1. 11-06 07:28 先写了一版临时估价（0.72 衰减 + 线性单价）；两小时后 09:13 上线正式价目表 `rateCard.js`，但只接了报价页，受众页从来没切过去。
2. 我连着六轮审研究端（内部文字、死链、按钮、移动端、崩溃页、付款死循环），每轮都打开过这两个页面，却一次也没做“全仓搜价格计算”，所以一直把这两页当正常。
教训：
- 价格只许调用，页面里不许出现公式；审价格先 grep 公式，再看文案。
- 同一个数字出现在两个页面，必须比对到分，不看“看起来差不多”。
- 看到两套算法，先问“哪一套是成本模型”，再决定删哪套。

## E-122 详情弹窗自己留了一份状态表和步骤表
现象：合同待签的项目，详情页状态直接印 `CONTRACT_SENT`；进度条把「需求」标成当前步骤，可它已经走到付款。已交付、已验收同样错。
原因：`BusinessProjectSheet` 自带 STEPS 和 stepIndex，工作台另有一份 STATUS_TEXT。新加的合同/交付/验收状态只补了工作台；`stepIndex` 找不到状态就 `return 0`，于是永远退回第一步。
教训：状态和步骤只能有一份。已加守卫：页面里定义 `STEPS` / `STATUS_TEXT`，或写 `statuses[x] || status`，检查直接失败。

## E-123 “报告已放行”有六种写法
现象：后端把报告置为 `SENT` 时，结果页能打开，但项目卡和详情弹窗显示“报告整理中”，验收按钮也不出现——客户能看却找不到入口。
原因：六处判断，五处只认 `APPROVED`，只有结果页认 `APPROVED | SENT`。
教训：一个业务事实只许一个判定函数（`isReportReleased`）。已加守卫：任何文件直接比较 `deliveryStatus === 'APPROVED'` 检查失败。

## E-124 “其他”选项把占位词当答案存下来了
现象：受访者勾了「其他」但没填内容，提交上去的答案是字符串 `Other: details`——“details” 这个词被当成他的话进了报告。
原因：勾选「其他」时直接写入 `'Other: details'`，界面上的输入框只是把这个占位词显示出来，没填就原样提交。
教训：占位词只许出现在 placeholder 属性里，不许进数据。已改为存 `Other: `，并在结果页把前缀按语言显示成「其他：」。

## E-125 报告重复、“待复核”是内部口径
现象：详情弹窗的四个数里有一项“报告”，交付物里又有一项“报告”；结果页对客户写“待复核”，那是我们内部的质检说法。
修复：删掉四个数里的“报告”（留交付物）；“待复核”改成“完成过快”，描述的是数据本身而不是我们的流程。
教训：客户页上的每个词都要能回答“客户看得懂吗、跟他有什么关系”。

## E-126 新建的项目在「项目」页里看不见
现象：客户点「新建研究 → 自助 → 填完创建」，进到问卷编辑器；再点「项目」，列表是空的——项目像是丢了。其实它还在，只是状态是草稿，被列表过滤掉了。
原因：`legacyVisibleInProjects` 把 DRAFT 全部隐藏，草稿只留在问卷编辑器里；而新建项目的入口直接把用户送到编辑器，用户回头就找不到。
修复：草稿也进列表（YouGov 的列表本身就有 Drafts 页签），只隐藏已取消的项目。
教训：不要用“藏起来”解决列表杂乱；藏起来的东西，用户会当成丢失。

## E-127 打不开的项目会“假装”成一个新问卷
现象：访问一个不存在的项目（删掉的、旧链接、手改 id），问卷编辑器显示「未命名问卷 / 草稿」，报价页还按 500 份算出一个价格——像模像样，其实项目不存在。
原因：两个页面 `getBusinessProject` 失败后只 catch 不处理，继续用 null 项目渲染。
修复：加载失败直接显示「这个项目打不开，可能已被删除」+ 返回工作区；不再进编辑器/报价页。
教训：取数失败要么重试，要么明确报错；拿 null 继续渲染等于编数据。

## E-128 顶部「问一句」把用户的话吞掉了
现象：在工作台顶部输入问题回车，跳到 AI 简报页，但对话是空的——输入的那句话没了。
原因：工作台用 `navigate(..., { state: { initialPrompt } })` 传话，AI 简报页从来没人读这个 state。
修复：AI 简报页读取后自动发第一条，发完清掉 state；顺便把该输入框的英文 placeholder 按语言显示。
教训：传过去的参数必须有人接；跨页面的 state 要写清消费方。

## E-129 点「表格」看到的是另一张图
现象：结果页有「图表 / 表格」切换，选「表格」出来的是横向条形图，不是数字表格。
原因：表格分支复用了条形图组件，只是换了个排列。
修复：表格分支输出真正的三列表格（选项 / 份数 / 占比）；「其他：xxx」在表格和图表行里也按语言显示。
教训：控件名字就是承诺，点了不兑现比没有这个控件更糟。

## E-130 AI 简报把上一个账号的 brief 留在了浏览器里
现象：A 账号在 AI 简报里写过研究决策、受众、市场，退出后 B 账号在同一台电脑登录，localStorage 里还留着 A 的原文（键名固定、签名就是 brief 原文）。
原因：生成幂等键写死在 `guanyisearch.business-ai-brief.generation.v1`，签名直接 `JSON.stringify` 了 brief 字段。
修复：键名带上用户 id，签名改存哈希，不再落原文。
教训：凡是写进 localStorage 的业务数据，都要问“换个人登录会看到吗”。

## E-131 问卷编辑器里 10 个图标按钮没有可读名字
现象：复制、删除、更多、AI 改题这些按钮只有图标和 `title`，读屏软件只念“按钮”。
修复：统一补 `aria-label`；现在页面上没有“无名按钮”。
教训：`title` 是鼠标提示，不是无障碍名字。

## E-132 英文界面里跳出中文日期
现象：英文账号打开报价页，价格锁定日期显示「11月18日」；金额格式也是中文习惯。
原因：判断写的是 `language === 'en'`，但应用里的语言代码是 `en-US` / `en-GB`，这个比较永远不成立，于是走了中文分支。
修复：统一用 `startsWith('en')` 判断；实测英文报价页无中文，金额显示 `$901.25`。
教训：语言代码是带地区的，别拿国家码当语言码比。

## E-133 繁体中文界面里混进简体
现象：zh-Hant 账号看到「帮助中心」「在线问卷」「确认问卷」「待审核」，和繁体正文混排。
原因：约 44 处 inline 判断写的是 `language.startsWith('zh') ? 简体 : English`，zh-Hant 也满足 startsWith('zh')，于是永远拿简体。
修复：`content/projectStatus.js` 增加繁体状态表与 `pick(语言, 简, 英, 繁)`；侧栏、帮助页、在线问卷、下一步按钮/提示/确认框改为三等分。其余 inline 文案仍待逐条补繁体。
教训：语言判断要区分简繁，不能只判断“是不是中文”。

## E-134 .env 被提交进了仓库
现象：`.gitignore` 写着 `.env`，但 `.env` 早已被 git 跟踪，忽略规则对它无效。
当前内容只有 `VITE_API_URL` 和 `VITE_TURNSTILE_SITE_KEY`——都是公开值（site key 本来就要给浏览器），所以没有真泄露；但这是坏习惯：哪天有人往里加一个非公开密钥，就会跟着提交。
处理：`git rm --cached .env`，本地文件保留，从此按 `.gitignore` 忽略。新增配置请只写进 `.env.example`。

## E-135 邀请链接的 next 参数没人用
现象：未登录点「登录后接受」，跳到 `/login?next=...`，登录完回到工作台，而不是回到那张邀请。
原因：`next` 参数生成了，但登录页没有读取它。
状态：未修（属邀请流程，等你排期）。
