# 流程审计：项目状态机 vs 正规研究流程

更新：2026-11-11 ｜ 对应代码 `src/pages/BusinessWorkspace.jsx`、`BusinessQuestionnaireStudio.jsx`、`BusinessProjectSheet.jsx`

## 一、正规流程（研究行业惯例，ISO 20252 / ESOMAR 口径）

1. 需求简报
2. 方案与报价
3. 合同或采购单（B2B 客户多数先走 PO，才能付款）
4. 付款 / 预付款
5. 问卷设计 → 内部质检（QA）→ 客户确认 → 上线
6. 投放回收（含配额监控）
7. 数据处理与报告
8. 交付与验收 → 归档

## 二、我们现在的状态机

```
DRAFT → SUBMITTED_FOR_REVIEW → QUOTE_REQUIRED → QUOTE_SENT
     → CLIENT_ACCEPTED → FUNDED → RECRUITING → LIVE → COMPLETED
                                                        ↘ CANCELLED
```

## 三、对不上的地方

| 正规步骤 | 现在的状态 | 问题 |
|---|---|---|
| 合同 / PO | 无 | 「接受报价」直接跳到付款。企业客户没有 PO 号付不了款 |
| 问卷质检 + 客户确认 | 无 | `FUNDED` 就能发布。没有「内部审核」「客户签字」两个状态 |
| 交付 / 验收 | 无 | `COMPLETED` 就是终态，没有「已交付」「客户验收」，也不能撤回 |
| 取消 | `CANCELLED` 裸状态 | 没有原因、没有退款关联 |

## 四、状态跳变没人管

前端只能挡按钮，真正的顺序校验必须在后端：

```
[ ] DRAFT 只能由创建者提交，不能直接 QUOTE_SENT
[ ] QUOTE_SENT 必须来自 QUOTE_REQUIRED，且必须挂在一条报价记录上
[ ] FUNDED 必须有已支付的 payment 记录，不能手工置位
[ ] RECRUITING/LIVE 必须在问卷发布之后
[ ] COMPLETED 必须有已生成的报告（或至少已放行）
[ ] 任何状态都不允许跳过 CLIENT_ACCEPTED → FUNDED
```

现在这些前端都没校验，后端不确定有没有。

## 五、缺的页面

| 步骤 | 现状 | 缺什么 |
|---|---|---|
| 简报 | 有（弹窗表单） | — |
| 报价 | 有（`/business/projects/:id/quote`） | — |
| 合同 / PO | 无 | 没有页面，也没有字段 |
| 付款 | 有（add funds / 支付链接） | — |
| 问卷设计 | 有（studio） | — |
| 问卷质检 / 客户确认 | 无 | 缺一个「提交审核 → 通过 → 客户确认」的列表与详情 |
| 投放回收 | 只有 0/200 一个数字 | 没有投放页（交接文档里也是空的） |
| 报告 | 无 | 没有报告编辑页 |
| 交付 / 验收 | 只有客户预览页 | 没有验收动作、没有归档 |

## 六、这轮已经修的

1. **付款前不能发布问卷**：`BusinessQuestionnaireStudio` 发布时校验项目必须是 `FUNDED/RECRUITING/LIVE/COMPLETED`，否则报错。
2. **进度条不再越过报价**：`QUOTE_SENT` 停在「报价」，`CLIENT_ACCEPTED` 才进「付款」。
3. **AI 建的问卷不再标成定制研究**：有问卷就算问卷调研，不再只看 `studyFormat`。
4. **项目详情里报价单独一行**：金额 + 已发出/已确认/已拒绝 + 有效期。

## 七、还要你们定的

1. 要不要加 `CONTRACT_PENDING`（合同/PO）状态？B2B 客户付款前通常需要。
2. 问卷发布前要不要「客户确认」这一步？要的话加 `QUESTIONNAIRE_REVIEW`。
3. 交付要不要 `DELIVERED → ACCEPTED` 两个状态，还是 `COMPLETED` 后直接归档？

这三个定了，我才能把页面和状态一起补齐；不定的话做出来还是会被说“跳步”。

## 八、补后的状态机与接口（要后端实现）

### 状态

```
DRAFT
 → SUBMITTED_FOR_REVIEW        客户提交需求
 → QUOTE_REQUIRED / QUOTE_SENT 我方出报价
 → CLIENT_ACCEPTED             客户接受报价
 → CONTRACT_SENT               我方发合同 / PO
 → CONTRACT_SIGNED             客户签回（B2B 可附 PO 号）
 → FUNDED                      收款确认
 → QUESTIONNAIRE_REVIEW        我方提交问卷，等客户确认
 → QUESTIONNAIRE_APPROVED      客户确认
 → RECRUITING → LIVE           投放回收
 → COMPLETED                   回收结束
 → DELIVERED                   报告发送
 → ACCEPTED                    客户验收（终态，可归档）
CANCELLED                      任意阶段，带原因
```

### 接口

```
POST /api/business/projects/:id/contract/send
  → 200 { project: { status: 'CONTRACT_SENT' } }
  权限：内部

POST /api/business/projects/:id/contract/sign      （客户侧）
  body { poNumber?: string }
  → 200 { project: { status: 'CONTRACT_SIGNED', poNumber } }

POST /api/business/projects/:id/questionnaire/submit-review
  → 200 { project: { status: 'QUESTIONNAIRE_REVIEW' } }
  前置：项目状态 ≥ FUNDED，问卷已保存

POST /api/business/projects/:id/questionnaire/client-approve   （客户侧）
  → 200 { project: { status: 'QUESTIONNAIRE_APPROVED' } }

POST /api/business/projects/:id/report/send
  → 200 { project: { status: 'DELIVERED', delivery: { status: 'APPROVED' } } }
  说明：发报告 = 同时放行结果页

POST /api/business/projects/:id/report/revoke
  → 200 { project: { status: 'COMPLETED', delivery: { status: 'REVOKED' } } }

POST /api/business/projects/:id/accept          （客户侧）
  → 200 { project: { status: 'ACCEPTED' } }
```

### 硬规则（后端校验，不能只靠前端）

1. 没有 `CLIENT_ACCEPTED` 不能进 `CONTRACT_SENT`
2. 没有 `CONTRACT_SIGNED` 不能置 `FUNDED`
3. `QUESTIONNAIRE_APPROVED` 之前不能 `RECRUITING/LIVE`
4. `COMPLETED` 才能 `DELIVERED`
5. 任何跳变返回 `409 INVALID_TRANSITION`
6. 每次状态变化写一条审计（谁、何时、从什么到什么）
